# WinDisplay 发送端（C#）

把电脑的画面发给 Tab5 的「无线显示」页，协议见 [`../PROTOCOL.md`](../PROTOCOL.md)。第一个目标平台是 Windows；
和平台无关的核心在 Linux 上也能编译、跑和测。

## 现状

已知不足：

- 注入不进去的时候：前台是权限更高的窗口（以管理员身份运行的程序、UAC 提示、锁屏）时系统不让普通权限的程序注入；Ctrl-Alt-Del、Win-L 注入不了。
  显示器睡着时，把它叫醒的那一下触摸系统不交给窗口（和平板上点一下黑屏只是亮屏一样；自检第一次跑时碰到过一次「第一下没收到」，推测是这个，
  自检现在会报显示器的状态，等它再睡着时复核）。主机的键盘布局不是美式时打出来的字不一样（协议「键盘」）。
- 发送进程被强行结束（`taskkill /f`；`windesk.sh` 到了 `--timeout` 也是这样结束它的）时来不及把注入进去还按着的键松开：
  那个键在电脑上会一直按着，到有人按一下它为止。正常退出、Ctrl-C、连接断开都会松开；关掉控制台窗口、程序里没人接的异常
  这两种也登记了钩子去松（Core 的 `ExitHooks`，`wdsend` 和托盘程序都用它；.NET 在这两种情况下会不会调到钩子是照文档写的，没有在 Windows 上一种一种试过）。
  注销 / 关机不用管：整个桌面会话都没了，按着的键跟着没了。
- 按着键的时候前台换成了权限更高的窗口（管理员身份运行的程序、UAC 提示）：松开的那一下也注入不进去，那个键会一直按着，同上。这是系统的规矩，程序绕不过去。
- 触摸板模式（见「托盘程序」；开关在 Tab5 上，要固件和发送端都是 2026-11-13 之后的版本——旧的一方不认得 INPUT_MODE，那时只有触摸一种方式；「触摸板加速」要两边都是加了 TPAD_GAIN 之后的版本，有一方旧就按电脑自己的倍数：现在的发送端 2 倍，只认得 INPUT_MODE 的那一版 3 倍）：两根手指的手势（右键、滚动）只有单元测试，`wd touch` 调试命令只有一根手指，要人用手指试；
  没有双指缩放、三指手势、长按；光标只在主显示器里走（Tab5 上显示的就是主显示器）。拖动到一半 Tab5 没了消息时左键不松开
  （松开就是把拖着的东西放下），要等连接断开（5~11 秒）才松。前台是权限更高的窗口时和触摸、按键一样注入不进去。
  其余几处（都没在真机上遇到过，先记着）：
  - 轻点 / 按住是按快照到达电脑的时刻算的（协议的 TOUCH 不带时间戳）：无线卡一下，按下和抬起之间隔出 300 毫秒以上这一下点击就丢了，
    长按的「按下」被耽误、和「抬起」挤在一起到会算成一次点击。双击的第二下是在第二次抬起时才注入的，两下点得很慢（合起来超过系统的双击时间，默认 500 毫秒）就成了两次单击。
  - 点击、滚轮不带位置，落在系统光标现在的地方：有副屏、人用真鼠标把光标留在副屏上时，在 Tab5 上轻点点到的是副屏（一滑动光标就回到主屏）。那台电脑只有一台显示器，没试过。
  - Windows 里开了「切换主要和次要按钮」（左手用鼠标）时，注入的左键按文档会被系统当成次要按钮：轻点变右键、两指轻点变左键。没处理、没验证。
  - 滚轮是一小份一小份发的（每次至少 1/12 格），新程序都认；把每条滚轮消息都当一整格的老程序里会滚得飞快。
  - 光标连着挪的 200 毫秒之内不重新读系统的光标位置：这期间人同时动了真鼠标、或者程序自己挪了 / 限制了光标（游戏），下一下注入会把光标拉回注入器以为的位置。
- 触点贴着屏幕边的情形没有实测（自检只点屏幕中间：点边上会点到任务栏、别的窗口的标题栏）。接触面已经裁到屏幕以内。
- 托盘程序没试过的：人在真桌面上用鼠标 / 手指点设置窗口（点了做什么有单元测试 `TrayActionsTests`；窗口上点的是不是那一行、对话框什么时候能点确定，
  是给真窗口发鼠标消息测的 `TrayUiTests`；界面的样子看的是画出来的快照，100% 和那台电脑实际的 125% 都看过）；标题栏是不是深色的（快照里没有标题栏）；
  开机启动（注册表里那一条实测写对了，没有真的注销再登录一次）；注销 / 关机时的收尾（接的是 `SystemEvents.SessionEnded`，照正常退出走，没试过）；
  任务栏换深浅色、改了缩放比例之后托盘图标跟着重画（接了 `SystemEvents` 的两个事件、尺寸按主显示器现在的缩放比例取，没有真的改一次试过）。
- 设置窗口不能用键盘操作：只有 Esc 关窗口，行不能用 Tab / 方向键选、回车点（对话框能用键盘）。
- 对话框的尺寸是打开那一刻按主显示器的缩放比例算的：在缩放比例不一样的另一台显示器上打开、或者拖过去，大小不跟着变（设置窗口会跟着变）。
  只镜像主显示器、那台电脑也只有一台显示器，没法试，先不做。
- 托盘程序用自己的一份配对（交给 DPAPI），和 `wdsend` 的不共用：同一台电脑两个程序都配对过的话，Tab5 的「已配对的电脑」里有两条同名的。

- 画面在动时压小：大片都在变的帧（变了的行超过四分之一屏）按「每帧不超过预算」降 JPEG 质量（最低 20），画面不再大片地动了（150 ms 没出过在动的帧）就按原质量补一遍
  （实测的帧率见 `../PROTOCOL.md`「流量控制」）。`-v` 每帧末尾打印用的质量、当时的预算、这一帧跟没跟上。
  画质在 **Tab5 上选**：主页面上那排四档的按钮——最佳画质 / 高画质 / 均衡（默认）/ 最佳速度。Tab5 连上之后用 PICTURE_MODE 报过来（第几档 + 它屏幕的帧周期）、
  连接中途变了再报（`../PROTOCOL.md`「画质」），会话从下一帧起按这一档来（`PictureMode.cs` 里是各档怎么做）：画面不动时的质量四档都是 90；
  高画质 / 均衡两档把帧率限在屏幕刷新率的 1/2、2/3（30、45 帧上下）（`FramePacer`），画面在动时的预算在这一档的范围里闭环调——跟得上的前提下尽量大（`BudgetControl.cs`，
  做法见 `../PROTOCOL.md`「流量控制」里「限帧率和预算的闭环」）；最佳速度不限帧率、预算同样闭环调；最佳画质不限帧率、不降质量。
  加档位之前的固件报的是一组质量和预算（PICTURE）：照它的固定，不限帧率；更老的不报，按默认值（60 / 40 KB）。
  托盘程序总是听 Tab5 的，并记着每台 Tab5 上次报的，下一条连接从第一帧起就用；`wdsend` 给了 `--quality` 或 `--motion-kb N`（0 = 不降）就按命令行的定死、不听 Tab5 的
  （握手里不声明认得 PICTURE_MODE / PICTURE），`--min-quality Q` 是在动时最低降到多少（不能在 Tab5 上调）。
  一帧只压一遍、质量是跟着上一帧调的，所以画面突变的那一帧可能超预算；整屏一直在动就一直是低质量，停下来才补。
  显示期间发送端把进程的定时精度提到 1 毫秒（`PreciseTimer.cs`；Windows 默认 15.6 毫秒，卡不准限帧率的拍子），连接结束还回去。
- 一帧压不进 Tab5 的单帧上限时会自动降 JPEG 质量，降了之后这次会话里不再升回去（Python 测试工具也是这样）。
  会话可能一连几小时，一帧特别重的画面会拖低之后的画质；以后可以做成慢慢回升。
- 自动发现的询问是广播，在无线上丢了没有人重发：一轮没问到要等 3 秒问下一轮（实测绝大多数一轮就问到）。
- 抓屏只支持 Windows 11，只抓主显示器。HDR 屏按 8 位 SDR 抓，颜色可能发灰或者过亮（没有 HDR 屏，没验过）。
- 抓屏出故障的几条路都没在真机上触发过：显示器拔插、显卡驱动重置（断了重开）、中途换分辨率或转屏（`WgcCapture` 按新尺寸重开抓屏会话）。
  单元测试只覆盖到它们周围：`CaptureSource` 这一层的「断了重开」（假的显示器）、`LatestSlot` 把系统回调里出的错交给取画面的线程、
  `GpuScaler` 换输入尺寸（合成的纹理）；`WgcCapture` 里按新尺寸重开会话、查显卡设备丢没丢这两段没有任何测试。
  锁屏、弹 UAC 的时候 Tab5 上显示什么也没看过。

## 结构

- `Proto.cs` 报文常量和打包 / 解析；`Tab5Link.cs` 一条连接：连上、握手、收发（握手之后逐报文加解密）；`FlowControl.cs` 流量控制的算法：平时 2 帧在途、跟得上画面源时可以多放一帧、最早那一帧的确认迟到时最多放到 4 帧（纯计算，不碰时钟）；
  `StripEncoder.cs` 画面 → 条带（各条带分到几个核上同时压；画面在动时按每帧字节数的预算调质量、停下来补清晰）；`DisplaySession.cs` 一次会话的主循环（画面来源实现 `IFrameSource`，输入事件经 `Touch / Key / Mouse` 回调）。
- 认证和加密（`../PROTOCOL.md`「认证和加密」）：`Handshake.cs` 发送端这一侧的握手（`LinkAuth` = 配对存储 + 报给 Tab5 的名字 + 配对密码和密码不对的次数）；
  `Pairing.cs` 配对：`PairingSecret`（密码 → `w0`，托盘程序存它、不存密码）、`PairingGate`（现在能不能配对：设了密码就能；密码不对累计满 10 次
  停止配对，等人在电脑上恢复；配对成功或改密码清零；次数跨连接累计，托盘程序要把它存盘；每发一个 PAIR 先占一次机会，好几条连接同时配对加起来也不超过 10 次）、
  SPAKE2 和 P-256 的点运算（BouncyCastle）；`SessionCrypto.cs` 配对密钥、X25519、会话密钥、
  逐报文的 ChaCha20-Poly1305（.NET 自带的）；`PairStore.cs` 自己的编号和配对过的 Tab5（JSON 文件，和 Python 工具同一种格式；
  `protect` / `unprotect` 两个钩子留给托盘程序接 DPAPI；写不进文件时抛异常、这一次的改动不算，内存里和文件保持一致）。
  **改密码要做三步**：`PairingGate.SetPassword(新密码, commit)`，`commit` 里 `PairStore.ForgetAll()`、再把新密码连同清零的次数一次存盘
  （`HostSettings.SaveSecret`）；完了取消正连着的会话。`commit` 是换了密码之后、拿着 `PairingGate` 的锁调的（这期间别的握手拿不到密码、记不了次数，
  用旧密码配出来的密钥存不进去），它抛了异常时密码和次数都退回原样；移除一台是 `PairStore.Forget` + 取消连着它的会话。
  正在握手的那一条来不及取消也没关系：握手开头对这台 Tab5 取一个记号（`PairStore.Mark`），走完时它被移除过、或者做过 `ForgetAll` 就不存，
  会话以 `AuthFailed`（`Revoked`）结束；移除别的 Tab5 不影响它。
  **设了密码就随时可以配对**；没设密码或者已经停止配对时，遇到没配对过的 Tab5、或者 Tab5 说它没有这把密钥，会话以 `AuthFailed` 结束，不发 PAIR、也不删自己存的配对。
  握手走完才存新配的密钥。带秘密标量的乘法不用库里默认的窗口法（定点的用梳状乘法，对端给的点用垫成固定位数的蒙哥马利阶梯）。
- 自动发现和自动连接（`../PROTOCOL.md`「自动发现」「结束之后能不能重连」）：`Discovery.cs` 的 `LanDiscovery` 问一轮
  （每块连着的网卡各往自己网段的广播地址发一个询问，收 300 毫秒的应答；只往 255.255.255.255 发的话系统只从默认路由那块网卡发）；
  `AutoConnect.cs` 的 `AutoConnector` 一轮一轮地问、挑一台去连、那条连接结束了再问：配对过的优先，一台配对过的都没有、现在又可以配对才连没配对过的；
  上一次没显示出画面就结束了的地址（认证没过、连不上、接了就断……）排到同一档的后面；连接结束后从不照原地址重连，都是重新问、有应答才连（Tab5 上的人退出之后它不再应答，自然就不连了）；
  一帧没显示就结束的先等（1 秒起加倍到 30 秒），显示过画面的马上再问。它只管「什么时候连、连哪一台」，一条连接怎么跑是调用方给的
  （一般就是 `DisplaySession.Run`）。`DropCurrent()` 断开正连着的那一条（改了密码、移除了配对之后调），`Wake()` 让它下一次等待不等（正等着就马上醒，不在等也记着一次）。`connect` 和 `Changed` 的处理函数抛的异常会从 `Run` 原样抛出去。
- 输入换算 `InputMapping.cs`（纯计算，注入由 Windows 专有部分做）：`HidKeyboard` 把 Tab5 发来的 8 字节键盘报文和已经注入的状态按集合比，
  给出要注入的动作（第一套扫描码；先松、再改修饰键、再按），`Repeat` 是该由注入的一方按主机设置连发的那个键，`ReleaseAll()` 在连接结束时调；
  `TouchMapper` 把横屏画面里的触点换成显示器上的像素（落在黑边上按下的触点到抬起之前都不算），每次给出当前所有触点，
  `Held` 是还按着的（系统要求按着不动也接着报），`Cancel()` 把按着的都作废（Tab5 没了消息时；给出要注入的那一帧「取消」），
  `ReleaseAll()` 在连接结束时调（也是作废，不是抬起），`Abandon()` 是系统把注入的触点收走了之后调（手还按着的到抬起之前都不算）。
- 触摸板模式 `Touchpad.cs`（纯计算）：`TouchpadMapper` 把 Tab5 的屏幕当成一块触摸板，触点快照 → 鼠标动作（`MouseAction`：挪光标多少、左右键按下 / 松开、滚轮多少）。
  Tab5 发的触点快照两种方式下一样，注入成触摸还是换成鼠标动作是发送端的事（用哪种、加速多少由 Tab5 报过来，见下面）。「一次接触」= 第一根手指按下到全部抬起：
  一根手指滑动挪光标（手指在画面上挪多远光标就挪多远，换成显示器的像素；每秒 150 像素以下不放大，1500 以上放大到头——几倍在 Tab5 的「触摸板加速」里选，默认 2 倍，中间按比例）；
  300 毫秒之内抬起、没挪出 20 像素算轻点 = 左键点一下（还分不清是轻点还是滑动的那一会儿光标不动，不然双击的两下落在不同位置）；
  轻点之后 250 毫秒之内再按下：马上抬起是又一次轻点（双击的第二下），按住滑动是拖动——左键在看出是滑动的那一刻（挪出 20 像素，或者按过了 300 毫秒再动）才按下、
  抬起才松，不在手指按下的那一刻就按（那时还分不清是不是两指手势的第一根手指：两根手指几乎从不落在同一份快照里，
  先按下的话「点一下、马上两指滚动」会多出一次双击）；两根手指轻点 = 右键；
  两根手指滑动 = 滚轮，内容跟着手指走（Windows 触摸板的默认方向），48 像素一格，一次接触只滚横竖里的一个方向；三根以上不算；
  两根手指的接触里一根先抬起，剩下那根到抬起之前不算。数字都是 `TouchpadMapper` 里的常量。
- 输入注入分两层。Core 的 `InputBridge.cs`：`InputBridge` 把上面两个换算接到注入的地方（`IInputSink`），加上两件按时间做的事——
  按键连发（Tab5 不做连发，系统对注入的按键也不会自己连发：最后按下的键按住过了主机设置的延迟，按主机设置的速度重复注入「按下」，欠的不补）、
  触点重报（手指按着不动时 Tab5 不发新快照，而 Windows 规定按着的触点要接着报，实测不报的话 0.5~1 秒之间被系统收走、程序收到的是一次普通的抬起：每 100 毫秒在原地重报一次）；
  一帧触摸没注入成、或者屏幕分辨率变了，手还按着的那些到抬起之前都不算。
  这两件事都是照着 Tab5 上一次报的状态接着做的，所以只在那份状态还新鲜的时候做（协议「按着的时候」）：有键 / 触点按着时 Tab5 每 200 毫秒发一个 HELD，
  发送端超过 700 毫秒没收到任何输入报文（Tab5 突然没了，连接要过 5~11 秒才断）就不再连发、不再重报——键留着不松（到连接结束时松），触点作废：
  注入一帧「取消」（`ContactPhase.Cancel`，`InjectTouchInput` 的 `POINTER_FLAG_UP | POINTER_FLAG_CANCELED`），程序把这次触摸当成没做完、不算点击。
  光是不再重报不行：系统收走触点时给程序的是普通的抬起，等于在那里点了一下（注入自检实测）。连接结束时手指还按着的也是这样作废。
  触摸怎么注入由 Tab5 说了算（协议「触摸方式」）：人在 Tab5 的设置页上选，Tab5 用 INPUT_MODE 报过来，会话的 `InputMode` 事件 → `pump.Mode`。
  每条连接从「触摸」开始（`ReleaseAll` 把它拨回去），报了触摸板模式之后触点交给 `TouchpadMapper`、经 `IInputSink.Mouse` 注入。
  触摸板的加速（快滑时光标最多放大到几倍）是一样的路：Tab5 用 TPAD_GAIN 报，会话的 `TouchpadGain` 事件 → `pump.TouchpadGain` → `TouchpadMapper.MaxGain`；
  每条连接从 2 倍开始（`ReleaseAll` 把它拨回去）。
  换方式的那一刻旧方式下按着的先收掉（触点作废 / 左键松开），手还按着的那些到全部抬起之前都不算。
  `InputPump` 给它配上时钟和后台线程，顺带每 100 毫秒读一次主机的键盘指示灯，变了就报出来；后台线程要 `Start()` 才起（先把事件挂好）。
  `Close()` 是进程要结束时用的：按着的都松开，之后再来的输入不算。
  Windows 专有的 `InputInjector.cs`：`SendInput`（`KEYEVENTF_SCANCODE`）和 `InjectTouchInput`（触点位置是主显示器上的物理像素，所以进程设成按显示器感知 DPI；
  设不成、现在又不是这种方式的话构造时就报错）；注入不成只报 `Warning`、不抛异常。鼠标动作（`Mouse`）也用 `SendInput`：
  光标是「读出现在的位置、加上要挪的、按绝对位置注入」（相对移动要过系统的指针速度和加速设置，挪多少就不由 `TouchpadMapper` 说了算），只在主显示器里走；
  连着挪的时候 200 毫秒之内接着上一次挪到的地方算，不重新读系统的光标位置。`InjectCheck.cs` 注入自检。
  用法（`wdsend` 的 `InputTool.cs` 就是这么接的）：挂好 `pump.LedsChanged` → `session.SetKeyboardLeds`、`pump.Faulted`，然后 `pump.Start()`；
  `session.Touch` / `session.Key` / `session.Held` → `pump.Touch` / `pump.Key` / `pump.Held`；
  **每次 `session.Run` 返回之后调 `pump.ReleaseAll()`**（连接结束时 Tab5 不会补发：按着的键松开，按着的触点作废）；触摸换算用的位置关系取自抓屏（`ScreenCaptureStats.Fit`，哪个线程都能读）。
- 托盘程序分三层，逻辑都在 Core、能在 Linux 开发机上测：
  `SenderHost.cs` 常驻的发送端——一直自动连接（`AutoConnector`），问到 Tab5 才打开画面来源、连接结束就关（没有连接的时候不抓屏），输入交给 `InputPump`，
  状态（`HostStatus`：查找中 / 等配对 / 连接中 / 等 Tab5 输密码 / 已连接 / 出错）变了报 `Changed`；这台电脑这边出了错不停，隔 5 秒再试
  （画面来源打不开也算这一类，不记成那台 Tab5 没连上；原因经 `Faulted` 报给日志，同一个原因连着出只报一次）；
  另外管三件人在电脑上做的事：`SetPassword`（照上面那三步）、`ResumePairing`、`Forget`——存不进文件时这一次不算，内存里退回到和文件一致
  （密码和密码不对的次数都还是原来的、停着的还停着），界面上不会显示成已经办好。`HostSettings.cs` 存配对密码算出来的 `w0`、密码不对的次数
  （同一个文件；改密码时两样一次写入）；
  `AtomicFile.cs` 先写临时文件再换名（`PairStore` 和 `HostSettings` 都用它）；`DataDirLock.cs` 数据目录的锁（同一份数据同一时刻只让一个进程动）。
  `TrayView.cs` 状态 → 设置窗口里的组和行（每行 = 标题 + 一个短的状态值 + 怎么画 + 点了做什么）、托盘图标和提示，纯计算；
  `TrayActions.cs` 点了一行之后做什么：该问的先问（对话框是接口 `ITrayPrompts`），再叫 `SenderHost` 去做，存不进去就告诉人。
  Windows 专有的两样在 `WinDisplay.Win`：`Dpapi.cs`（给 `PairStore` / `HostSettings` 的 `protect` / `unprotect`）、`AutoStart.cs`（当前用户的 Run 项）。
  `src/WinDisplay.Tray` 只管画和接线：`Program.cs` 入口、命令行、一个桌面只跑一份、占住数据目录；`TrayApp.cs` 托盘图标、右键菜单、设置窗口的开关、日志；
  `SettingsPanel.cs` 自己画的设置窗口（按下和松开得是同一行才算点：按「是不是同一行」认，不按排在第几个认，内容刷新、行挪了位置也不会点到别的行）；
  `Dialogs.cs` 确认 / 看原因 / 输密码三个对话框；`Icons.cs` 现画的托盘图标（三种，跟着任务栏深浅色和主显示器的缩放比例）；`Theme.cs` 颜色和字体；`Snapshot.cs` 把界面画成 PNG。
- 抓屏分两层。和平台无关的在 Core：`ViewFit.cs` 一台显示器的画面在 1280×720 里占哪一块（等比、居中，四周补黑）；
  `CaptureSource.cs` 把一次打开的抓屏（`ICaptureBackend`）接成画面来源，抓屏断了隔 1 秒重开、这期间会话不断（Tab5 停在最后一幅）；
  `LatestSlot.cs`「只留最新一个」的交接位（系统回调线程 → 取画面的线程；回调里出的错记下来，取的时候抛出去）；
  `LimitedSource.cs` 给画面来源加帧数 / 时间上限；`FramePacer.cs` 限帧率的节拍（`wdsend --fps` 和画质的高画质 / 均衡两档用；取得慢了、没有连接的那一阵欠下的帧不补发）；`PictureMode.cs` 画质的四档各自怎么做；`BudgetControl.cs` 闭环调「画面在动时每帧的预算」（纯计算，不碰时钟）；`PreciseTimer.cs` 把定时精度提到 1 毫秒；`ReferenceScaler.cs` 缩放的对照实现（CPU、双精度，只给测试和自检用）。
  Windows 专有的在 `WinDisplay.Win`：`WgcCapture.cs` 用 Windows.Graphics.Capture 抓一台显示器，只留最新的一帧；
  `GpuScaler.cs` 在显卡上按面积平均缩成 1280×720 再读回（读回的只有 3.7 MB，和屏幕分辨率无关）；`Gpu.cs` 设备和 WinRT 之间的转换；
  `CaptureCheck.cs` 抓屏自检；入口 `ScreenCapture.OpenPrimary()`。
  工程不叫 `WinDisplay.Windows`：在那个命名空间里写 `Windows.Graphics.Capture` 会被当成 `WinDisplay.Windows.Graphics`。
- `wdsend` 编两份：`net10.0`（Linux 和 Windows 都能跑，只发测试画面，声音只有生成的正弦波 `--tone`）和 `net10.0-windows10.0.22621.0`（多了 `--screen`、`--screen-check`、`--input`、`--inject-check`、`--audio`、`--audio-check`）。
- 声音（协议「声音」；Tab5 在 HELLO 里说能收才发）：
  `Audio.cs`：`IAudioSource`（声音来源：`Start(sink)` 开始抓，抓到一段 48 kHz 双声道 16 位的 PCM 就调 sink，返回的对象 Dispose 之后不再调）、
  `AudioQueue`（排着等发的声音，最多 200 ms，放不下扔最旧的）、`SilenceGate`（连着半秒全是 0 之后不发，来了声音再发：
  开着一路声音却不出声的程序不白占 1.5 Mbps）。
  `Tab5Link.QueueAudio`：哪个线程都能调。发送这时空着就当场发掉；发画面的线程正占着就留在队列里，由它在下一个条带之前发
  （`SendFrame` 是一个条带一个条带发的）。每个用完发送锁的地方放锁之后都再看一眼队列（`PumpAudio`），不然最后一段会等到下一次有人发东西。
  发声音时发现连接断了不往抓声音的线程上抛：把连接关掉，读报文的线程报出来，会话按掉线处理。
  `DisplaySession` 握手走完后 `Start`，连接结束时先 `StopAudio()`（BYE 是最后一个报文）、关连接、再停来源；`SessionResult.AudioSentMs` / `AudioDroppedMs`。
  `WinDisplay.Win/LoopbackAudio.cs`：默认播放设备的 WASAPI 环回，只旁听、不动电脑的声音设置。格式让系统转（`AUTOCONVERTPCM`），事件驱动（10 ms 一段）；
  电脑没有东西在放时系统不给数据；默认设备换了、设备没了隔 1 秒重开。COM 接口是照 `Gpu.cs` 的写法直接按虚表调的，没有加依赖包。
- 会话的结束方式见 `SessionEnd`，结束之后能不能自己重连（协议「结束之后能不能重连」；重连是托盘程序的事，会话不管）：
  - `Dropped`（意外断开）、`ConnectFailed`、`ProtocolError`：可以自动重连。
  - `DeviceBye`（Tab5 那边的人退出，或者在密码框上点了取消）：不照原地址重连，回到广播询问，等 Tab5 应答了才连。
  - `AuthFailed`（认证没过，哪一种见 `SessionResult.AuthFailure`）：`Forgotten`、`KeyMismatch`、`Revoked` 可以重连；
    `NotPaired`、`WrongPassword` 说明现在不能配对（没设密码，或者密码不对记满了次数、已经停止配对）——到能配对之前不要再连没配对过的 Tab5。
  - 一条连接一帧都没显示出来就结束的（上面哪一种都算），下一次连之前要等（1 秒起、每次加倍、最长 30 秒），那个地址下一轮排到同一档的后面。
- 配对走到哪一步经 `Pairing` 事件报出来。它和 `PairingGate.WrongCountChanged` 的处理函数都是握手停下来等着的：**不许等别的线程、不许做耗时的事**
  （Tab5 每一步只等 5 秒）。
- `Run` 抛异常 = 本端的代码出了错（画面来源、编码器、事件回调，或者握手走完时配对存不进文件——这一种是 `PairStoreException`），抛的是原来那个异常；抛之前连接已经收干净。
- 同一个 `DisplaySession` 可以一次接一次地 `Run`（掉线重连）。**先有画面再连接**：来源还没给过画面时不去连 Tab5；
  每条连接的第一帧先问来源有没有新画面（不等），没有就发会话手里最近的那一幅，所以画面来源只在画面变了的时候给新的就行
  （抓屏接口本来就是这样），重连时不用重给。这条连接上配过对（等人输密码可能一两分钟）也一样先问一下。
- 选项（`SessionOptions`）在构造会话时检查，越界抛 `ArgumentOutOfRangeException`，不会等到连上之后才出错。
- 键盘指示灯用 `SetKeyboardLeds`：只是记下状态、立刻返回（键盘钩子里也能调），会话在两帧之间发出去，每次连上后自动补发最新的。
- 取消（`Run` 的 `CancellationToken`）在连接、握手、等人在 Tab5 上输密码、发送卡住时都很快生效：一般几十毫秒，Tab5 不收数据也不关连接时最坏约 0.7 秒
  （正在跑的事件回调要等它跑完）。

## 编译和测试（Linux 开发机上）

```bash
cd windisplay/sender
dotnet test WinDisplay.slnx -c Release     # 单元测试（xunit），不需要真机和 Python；密码学对的是 ../testvectors/v2.json
scripts/mockcheck.sh                                 # 对着 ../tools/wd_mock_tab5.py 的集成检查（要带 numpy 和 PIL 的 python3），含配对和认证
dotnet src/WinDisplay.Cli/bin/Release/net10.0/wdsend.dll 192.168.1.50 --password 2468 --pattern scroll --frames 300   # 对着真机，第一次：配对
dotnet src/WinDisplay.Cli/bin/Release/net10.0/wdsend.dll 192.168.1.50 --pattern scroll --frames 300                   # 配对过之后不用密码
dotnet src/WinDisplay.Cli/bin/Release/net10.0/wdsend.dll auto --pattern scroll --frames 300                           # 不填地址：广播询问，连应答的那台
dotnet src/WinDisplay.Cli/bin/Release/net10.0/wdsend.dll auto --stay --pattern scroll --frames 0 --fps 10             # 一直自动连接，到 Ctrl-C 为止
```

**自动发现。** 地址写 `auto`：广播询问（一轮收 1 秒，最多问 3 轮），连应答的那台——配对过的优先，没配对过的要给 `--password` 才连。
加 `--stay` 就一直自动连接（托盘程序做的就是这件事）：问到 Tab5 就连，连接结束了再问，直到 Ctrl-C 或者画面发完（`--frames` / `--seconds`）；
Tab5 上的人退出之后它不再应答，要重新打开「无线显示」页才会再连上（3 秒问一轮）。`--broadcast 地址` 只往这一个地址问
（`mockcheck.sh` 用它把询问限制在本机回环，不往局域网里广播）。

**配对。** `--password` 是配对密码：没和这台 Tab5 配对过（或者它那边没有这把密钥了）就用这个密码配对，在 Tab5 弹出的密码框里输同一个；
配对过的直接认证，给不给都一样。没给密码又要配对：退出码 3。`--forget` 先忘掉所有配对，`--name` 是报给 Tab5 的名字（默认机器名）。
`wdsend` 的配对存在 `--pair-store` 指的文件里，默认是用户目录下的 `WinDisplay/wdsend-pairings.json`
（Windows：`%LOCALAPPDATA%`；Linux：`~/.local/share`），明文 JSON、里面是密钥，只给测试用；托盘程序的配对另存、交给 DPAPI，不和它共用。

**声音**（`--audio`）：电脑本机照常出声，Tab5 上放多响在 Tab5 的「无线显示」页上调。不想半夜出声地验证：在那台电脑的桌面会话里放一段幅度很小的
测试音（比如 −60 dBFS 的 1 kHz WAV，`powershell (New-Object Media.SoundPlayer 'x.wav').PlaySync()`），`--audio-check` 看抓到的是不是那个幅度；
发给 Tab5 之后用它的串口命令 `wd listen 1000` 让麦克风量扬声器里有没有那个频率，`wd` 看断音次数。Linux 开发机上没有声卡，用 `--tone 1000 [--tone-db -50]`
发生成的正弦波，走的是同一条发送的路。

**注入自检**（`--inject-check`）在主显示器中间开一个置顶的小窗口，只往它身上注入：屏幕坐标是不是物理像素（系统报的尺寸对显示模式的分辨率，顺带报缩放比例）、
点一下（位置对不对）、两根手指、作废一个触点（窗口收到的是取消、不折成点击）、按着不动不重报多久被系统收走、收走时窗口收到什么（量数字）、
照投屏时的做法按 3 秒不被收走、按着的时候 Tab5 没了消息 / 连接结束时手指还按着（触点作废：窗口收到的是取消，不是抬起，也不变成点击）、
触摸板模式的鼠标动作（光标沿屏幕正中横竖各一个像素一个像素地挪一遍、每一步读回来都是那个像素；光标被别人挪过之后从现在的位置起算；
左键、右键、滚轮的方向和多少、拖动；再走整条路：一根手指轻点 = 左键且光标不动、慢慢滑 100 像素光标挪的距离、两根手指轻点 = 右键）、
字母键和方向键的扫描码、Shift + 1 打出 `!`、按住连发的次数、按住的时候 Tab5 没了消息（不再连发、键不松开，又有消息了接着连发）、
Caps Lock 之后读到的指示灯、Num Lock 的扫描码。
它要抢焦点、往自己的窗口里打几个字、把 Caps Lock 和 Num Lock 各按几下（结束时照指示灯的实际状态补回开始时的样子）、
把光标挪遍屏幕正中的一横一竖（只是经过，不点；结束时放回原处），所以**最近 10 秒有人动过键盘鼠标就不跑，
锁屏着、开着 UAC 提示时也不跑**；触摸和鼠标的点击、滚轮只在要点的位置上是它自己的窗口时才注入（上面盖着别的置顶窗口就不点，那一项判不符），
按键只在自己的窗口是前台时才注入（按住的那几项每 50 毫秒看一次，焦点没了马上松开）。显示器睡着时它先点一下把屏幕叫醒。

**`--input`** 要和 `--screen` 一起用（触摸的位置按抓到的屏幕换算）。从 Linux 开发机遥控试的时候，Tab5 这头用串口 `kbd key <行> <列> down|up` 发按键——
**它会打进那台电脑上当时有焦点的窗口**，所以只发修饰键（`kbd key 4 0 down` / `up` 是 Ctrl），别的键等人在场时试。触摸只能用手指。
触摸照 Tab5 上选的方式注入（设置页上的「触摸板模式」开着就是触摸板模式，手势见「托盘程序」）；加 `-v` 能看到 Tab5 报过来的那两行 `← INPUT_MODE 触摸板`、`← TPAD_GAIN 2.0 倍`。
从 Linux 开发机遥控时用串口 `wd tpad on|off` 拨那个开关、`wd tpad accel 0~3` 换加速的档位（关 / 低 / 中 / 高）。

## 托盘程序

日常用的是它：常驻在托盘里，Tab5 上打开「无线显示」页它就自己连上去，显示这台电脑主显示器的画面，Tab5 上的触摸和键盘注入这台电脑；
Tab5 上的人退出、页面关掉，它就回去等。只能在 Windows 11 上跑。
连着的时候这台电脑正在放的声音也从 Tab5 放出来（2026-11-14 起；电脑本机照常出声，托盘程序不动电脑的声音设置）。放多响、要不要静音在 Tab5 上调：
主页面的「音量」，拉到 0 就是不出声。托盘程序这边没有声音的设置；抓不了声音（没有播放设备……）只记一行日志，画面照常。

```bash
scripts/wintray.sh install       # 从 Linux 开发机装到那台 Windows 电脑上（或者更新）：同步 + 编译 + 发布，整份拷到 %LOCALAPPDATA%\Programs\WinDisplay 旁边再换上去
                                 # （换不上去时装着的那一份原样不动、重新起来），然后起在桌面会话里
scripts/wintray.sh uninstall     # 退出、关掉开机启动、删掉程序（数据留着）
scripts/traysnap.sh [--desk] [目录]   # 看界面：把设置窗口的几种局面、对话框、托盘图标画成 PNG 取回来（不连 Tab5、不截桌面；--desk 照那台电脑真的缩放比例画）
scripts/wintray.sh start | stop | password <密码> | log | wipe    # 真机测试用的那一份：跑源码目录里编译出来的，数据放远端 .work\traydata
```

在 Windows 上自己装也行：`dotnet publish src\WinDisplay.Tray -c Release -o "%LOCALAPPDATA%\Programs\WinDisplay"`，然后运行里面的 `WinDisplayTray.exe`
（要装着 .NET 10 的桌面运行时）。更新时先 `WinDisplayTray.exe --exit` 再覆盖。

- **头一次用**：没设过配对密码时，程序起来会自己打开设置窗口，「配对密码」那一行是红的，点它设一个；然后在 Tab5 上打开「无线显示」页，
  Tab5 弹出密码框，输同一个密码，之后就不再问了。改密码会移除所有配对过的设备（先确认）。
- **界面**：左键点托盘图标打开设置窗口，右键是「设置 / 退出」。设置窗口四组：连接（状态、连着的设备）、配对（配对密码）、已配对的设备（点一行移除）、通用（开机启动）。
  每行一个标题加一个短的状态值；要人动手的是红的，点一下直接去办（没设密码 → 设密码；密码连着不对 10 次停了配对 → 恢复；出错 → 看原因）。
  托盘图标三种：没连着、连着、要人动手（带红点）——设置窗口里有红的行，图标就带红点，鼠标停上去的提示说的是那件事。
- **触摸板模式**（开关在 **Tab5** 上：设置页上的「触摸板模式」，默认关，存在 Tab5 里；电脑这边没有开关——用的时候人在 Tab5 跟前，
  电脑可能连显示器都没接。Tab5 连上之后把现在的方式报过来。显示期间 Tab5 自己的界面停着，要换方式先从左边缘右滑退出显示——Tab5 停在「无线显示」页、暂停着不接受连接——拨完点「开始显示」）：关着时 Tab5 上的触摸照原样注入成触摸
  （手指点哪就点哪）；开着时 Tab5 的屏幕当触摸板用，换成鼠标动作——一根手指滑动挪光标（滑得快挪得远），轻点 = 左键，
  轻点之后马上再按住滑动 = 拖动（马上再点一下 = 双击），两根手指轻点 = 右键，两根手指滑动 = 滚动（内容跟着手指走，横竖都行）。
  电脑桌面上的东西对指尖来说太小、点不准的时候用它。
  光标快慢也在 Tab5 上调：设置页上的「触摸板加速」（关 / 低 / 中 / 高，默认中）——手指慢慢滑时光标总是和手指挪得一样远，
  滑得快时最多放大到 1 / 1.5 / 2 / 3 倍。Tab5 连上之后报过来；老固件不报，按 2 倍。
  画面清楚还是流畅也在 Tab5 上选：主页面上的画质（最佳画质 / 高画质 / 均衡 / 最佳速度：画面在动时要清楚、要限在多少帧、还是尽量快）。
  和触摸板的开关一样，显示期间选不到：先从左边缘右滑退出显示，选完点「开始显示」，重新连上就按新的。
  主页面的「性能信息」打开后，显示期间画面顶上靠右叠一行帧率和延迟（Tab5 自己画的，延迟只算 Tab5 这一侧）。
- **数据**在 `%LOCALAPPDATA%\WinDisplay\`：`pairs.bin`（配对）、`host.bin`（配对密码算出来的数据、密码不对的次数）都交给 Windows 的数据保护（DPAPI，只有这个用户解得开），
  `tray.log` 是日志（启动的版本、每条连接怎么结束的、出了什么错；界面上不显示）。读不懂的文件不会被悄悄当成没有：程序说明原因后退出。
  同一份数据同一时刻只让一个进程用（程序只在启动时读文件，两个进程各写各的会互相盖掉）：常驻的那一份一直占着目录里的 `.lock`，
  ssh 进来的、远程桌面里的另一份也都看得见它。
- **命令行**（给安装脚本和调试用）：不带参数 = 常驻；`--data-dir 目录` 数据放别处；`--set-password 密码` 不开界面设密码（有托盘程序正在用这份数据时拒绝）；
  `--exit` 叫正在跑的那一份正常退出并等它退完；`--autostart on|off` 开 / 关开机启动；`--snapshot 目录` 把界面画成 PNG。
  同一个登录会话（桌面）里只跑一份，再起一份 = 叫先起的那一份把设置窗口打开。
  退出码 0 = 成了、1 = 没成、2 = 参数不对、负的 = 程序里有没人接的异常。没成的原因：常驻的和 `--set-password` 写在 `tray.log` 里；
  `--exit`（等了 15 秒那一份还没退出）和 `--autostart`（注册表写不进去）各只有这一种，不写日志。它没有控制台，经 ssh 用 `start /wait` 跑的时候退出码要专门传回来（见 `scripts/winenv.sh` 的 `RC`）。
- **开机启动**是当前用户注册表 Run 项里的一条，指着程序现在的路径；`wintray.sh install` 头一次装时打开，之后照设置窗口里那个开关，更新不动它。

`winsync.sh` 把 `../testvectors/` 也带过去（远端在 `C:\_\src\WinDisplay\testvectors\`），那边的单元测试对的是同一份向量。

`winsync.sh` 经 ssh 跑，进去的是会话 0，没有桌面：单元测试（显卡能用）和发测试画面可以，抓屏不行。
`windesk.sh` 用一次性的计划任务把 `wdsend` 起在登录用户的桌面会话里（没有窗口），跑完把输出取回来；那台电脑上要有人登录着。
计划任务默认的优先级起出来的进程是「低于正常」优先级，机器一忙帧率就偏低：`winenv.sh` 的 `task_run` 建完任务先把它改成普通再跑
（`windesk.sh` 和 `wintray.sh` 都经它起；**2026-11-13 之前用 `windesk.sh` 量的帧率都是在「低于正常」优先级下量的**）。
它不管怎么退出（跑完、超时、Ctrl-C、被 kill）都先把那边这次起的 `wdsend` 结束掉；给了 `--screen` 没给 `--seconds` 时自动补一个比时限短 10 秒的。
被 `kill -9`、或者收尾时连不上那台电脑的时候做不到，只能靠 `--seconds` 到点自己停。
抓屏自检不存盘、不外发屏幕内容；判「符合」要黑边全黑、至少 40 dB、差 2 以上的像素不超过 1%、比故意弄错的对照高 6 dB 以上
（屏幕静止时实测 72.6 dB）。屏幕上有东西在动时两条路抓到的不是同一瞬间，判成不符就等静下来重跑。

`wdsend --help` 看参数。退出码和 `../tools/wd_send_test.py` 一致：0 正常结束；1 没连上 / 参数不对（连接之前就报，并打印用法）/
画面压不进 Tab5 的上限；2 连接中途断了或对端不守协议；3 认证没过（没配对过又没给密码、密码一直不对、对面没有配对密钥）；130 没发完被 Ctrl-C 打断。

真机测试前 Tab5 要停在「无线显示」页；经串口远程操作时先发 `disp awake on`（息屏时 `open wdisp` 会被拒），测完发 `disp awake off`。
